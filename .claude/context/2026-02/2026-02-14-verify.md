## Problems & Solutions

**Problem 1**: MCP tools visible in main context when SKILL.md executes
- Root cause: SKILL.md runs in main → allowed-tools setting is advisory only
- Original attempt: Strengthen prompt to avoid direct MCP use (v0.22.0)
- Result: Insufficient - users would still see and misuse tools
- Solution: Structural separation - move pipeline to dedicated agent with restricted tool access

**Problem 2**: Skill could not fully prevent tool access through prompting alone
- Reason: Main context sees all available tools regardless of allowed-tools config
- Solution: Remove logic from main context entirely by delegating to sub-agent

## Decisions

1. **Orchestrator as separate agent (not generic writer)**
   - Rationale: This logic is specific to verify-web-ui domain, needs browser tools only, runs pipeline repeatedly
   - Decision: Use dedicated role instead of writer pattern

2. **Direct Task invocation from command (skip skill)**
   - Rationale: Skill was only delegating anyway - unnecessary layer
   - Decision: Command directly invokes Task(orchestrator)
   - Benefit: Clearer dataflow, one fewer context load

3. **No PARA extraction this session**
   - Rationale: Session was implementation-focused, no architectural concepts emerged for reuse
   - Already covered in v0.22.0 session: "Tool access control separation"
