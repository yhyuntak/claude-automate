# AC 추출 기준

## AC 작성 기준

- "통과/실패" 판정이 가능한 문장으로 작성
- 하나의 AC = 하나의 검증 포인트
- 모호한 표현 금지 ("잘 동작한다" ❌ → "200 응답을 반환한다" ✅)

## 변환 예시

| 요구사항 | AC |
|---------|-----|
| "로그인 기능" | 올바른 credentials → 200 + token 반환 |
| | 잘못된 credentials → 401 반환 |
| | 3회 실패 → 계정 잠금 |
| "세션 저장" | 저장 후 파일이 .claude/context/에 존재 |

## 테스트 가능 분류

| 유형 | 예시 | 테스트 가능 |
|------|------|------------|
| 조건부 동작 | "3회 실패 → 잠금" | ✅ |
| 입출력 명세 | "POST /login → 200 + token" | ✅ |
| 상태 변화 | "결제 후 잔액 차감" | ✅ |
| 감성적 | "깔끔한 UI" | ❌ |
| 탐색적 | "일단 만들어보자" | ❌ |

테스트 가능 AC가 하나도 없으면 → TDD 없이 일반 구현.

## 사용자 확인

AC 목록을 AskUserQuestion (multiSelect: true)으로 제시.
수정/삭제/추가 가능. 확인 후 /oracle으로 핸드오프.
