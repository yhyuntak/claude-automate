# 적응형 하네스 (Adaptive Harness)

> 사용할수록 똑똑해지는 AI 제어 시스템

---

## 개요

**적응형 하네스**는 사용자의 작업 패턴을 학습하여 점진적으로 최적화되는 AI 제어 시스템입니다. 처음엔 표준 설정으로 시작하지만, 사용할수록 당신의 스타일, 선호도, 작업 패턴에 맞춰 진화합니다.

### 한 마디로

"처음엔 초보 운전자처럼 조심스럽게 묻지만, 쓸수록 당신의 의도를 미리 파악하는 베테랑 운전자가 됩니다."

---

## 영감의 원천

### Kimi K2.5 PARL

**오케스트레이터 학습 방식**에서 영감을 받았습니다.

- 단순히 에이전트를 호출하는 것이 아니라, **어떤 순서로 호출할지를 학습**
- 보상 기반 최적화: 성공한 패턴은 강화, 실패한 패턴은 약화
- 사용자 피드백(승인/거부)을 학습 신호로 활용

### Opus 4.6

**세션 전체 구조 파악**에서 영감을 받았습니다.

- 첫 번째 응답 전에 전체 구조를 먼저 파악
- 세션 전반에 걸쳐 지시사항을 일관되게 유지
- 컨텍스트 보존을 통한 연속성 확보

### Reinforcement Learning - Experience Replay

**과거 경험 재활용**에서 영감을 받았습니다.

- 과거의 성공적인 경험을 저장 (Checkpoint)
- 유사한 상황에서 성공 패턴을 재사용 (Replay)
- 랜덤 샘플링으로 과적합 방지

## 핵심 비유

### 운전 학습 과정

**초보 운전자 (첫 세션)**
```
"좌회전 하시겠습니까?"
"차선 변경 하시겠습니까?"
"속도를 높이시겠습니까?"
```
→ 모든 것을 확인하며 조심스럽게 진행

**경험 쌓인 운전자 (10회 세션 후)**
```
"이 시간대엔 항상 이 경로를 선택하시네요"
"이 타입의 작업엔 주로 Sonnet을 선호하시네요"
"평소 패턴대로 진행할까요?"
```
→ 사용자의 패턴을 이해하고 제안

**베테랑 운전자 (100회 세션 후)**
```
"금요일 오후 3시, /start-work 호출
→ 지난주와 같은 백로그 작업 예상
→ explore → writer → pattern-checker 순서로 준비
→ Sonnet tier 기본 설정
→ 승인 대기 중"
```
→ 의도를 미리 파악하고 최적 경로 제시

## 구성요소 상세

### 1. Session Modes

작업의 성격에 따라 세 가지 모드로 세션을 구분합니다.

#### Fast Mode

**언제**: 빠른 확인, 간단한 수정, 루틴 작업

**특징**:
- 기본 Tier: Haiku
- 최소한의 분석
- 빠른 응답 우선
- 사용자 확인 최소화

**예시**:
```
- 오타 수정
- 간단한 설정 변경
- 파일 위치 찾기
- git status 확인
```

#### Standard Mode (기본값)

**언제**: 일반적인 개발 작업

**특징**:
- 기본 Tier: Sonnet
- 표준 분석 프로세스
- 균형잡힌 속도/품질
- 중요한 결정만 확인

**예시**:
```
- 새 기능 구현
- 버그 수정
- 리팩토링
- 문서 작성
```

#### Deep Mode

**언제**: 복잡한 아키텍처 결정, 전략적 작업

**특징**:
- 기본 Tier: Opus
- 전체 구조 먼저 파악
- 깊은 분석 우선
- 주요 단계마다 확인

**예시**:
```
- 아키텍처 설계
- 복잡한 알고리즘 구현
- 대규모 리팩토링
- 보안 관련 작업
```

---

### 2. Meta-Learning

사용자의 패턴을 학습하여 개인화된 하네스를 만듭니다.

#### 무엇을 학습하는가?

**Tier 선호도**
```
"이 사용자는 탐색 작업에 주로 Sonnet을 선호한다"
→ 다음부터 Sonnet을 기본값으로 제안
```

**작업 패턴**
```
"feature 구현 시 항상 explore → writer → checker 순서"
→ 동일 패턴 감지 시 자동 제안
```

**승인 스타일**
```
"사용자는 중요한 결정만 승인하고, 루틴 작업은 바로 진행 선호"
→ 승인 빈도 조절
```

**시간대/요일 패턴**
```
"금요일 오후엔 간단한 작업 위주"
→ Fast Mode 우선 제안
```

**실패 패턴 회피**
```
"이 Agent 조합은 과거 3번 실패"
→ 다른 조합 제안
```

#### 학습 데이터 소스

- 세션 기록 (.claude/context/)
- Checkpoint 누적 데이터
- 사용자 승인/거부 이력
- Auto Memory (.claude/memory/)
- 에이전트 실행 결과

---

### 3. Checkpoint & Replay

성공한 작업 패턴을 저장하고 재사용합니다.

#### 무엇을 저장하는가?

**에이전트 구성**
```json
{
  "agent_sequence": ["explore", "writer", "pattern-checker"],
  "tiers": ["sonnet", "sonnet", "haiku"],
  "parallel_groups": []
}
```

**작업 시퀀스**
```json
{
  "steps": [
    {"agent": "explore", "input": "...", "output": "..."},
    {"agent": "writer", "input": "...", "output": "..."},
    {"agent": "pattern-checker", "input": "...", "output": "..."}
  ]
}
```

**결과 및 메타데이터**
```json
{
  "task_type": "feature-implementation",
  "success": true,
  "duration_seconds": 180,
  "user_approvals": 2,
  "timestamp": "2026-02-07T10:30:00Z"
}
```

#### 언제 Replay 하는가?

**유사 작업 감지**
```
현재 작업: "새 기능 구현"
과거 Checkpoint: "feature-implementation" 타입 5개 발견
→ 가장 성공률 높은 패턴 제안
```

**Cold Start 회피**
```
새 프로젝트 시작 시
→ 유사 프로젝트의 Checkpoint 가져오기
→ 빠른 적응
```

**실패 후 대안 탐색**
```
현재 접근 실패
→ 과거 유사 상황의 다른 Checkpoint 탐색
→ 대안 제시
```

## 학습 루프

```
┌──────────────────────────────────────────────────────────┐
│                     1. 사용                               │
│  사용자가 하네스를 통해 작업 수행                          │
│  - 명령 호출                                              │
│  - 에이전트 실행                                          │
│  - 승인/거부 결정                                         │
└──────────────┬───────────────────────────────────────────┘
               │
               ↓
┌──────────────────────────────────────────────────────────┐
│                     2. 기록                               │
│  모든 상호작용을 구조화하여 저장                           │
│  - Session Context: 세션 내 컨텍스트                      │
│  - Checkpoint: 성공 패턴                                  │
│  - Meta Events: 승인/거부, 선호도                         │
└──────────────┬───────────────────────────────────────────┘
               │
               ↓
┌──────────────────────────────────────────────────────────┐
│                     3. 학습                               │
│  누적된 데이터에서 패턴 추출                               │
│  - 빈도 분석: 어떤 조합이 자주 성공했나                    │
│  - 상관관계: 작업 타입 ↔ 최적 Agent 조합                 │
│  - 시간 패턴: 요일/시간대별 선호도                        │
└──────────────┬───────────────────────────────────────────┘
               │
               ↓
┌──────────────────────────────────────────────────────────┐
│                     4. 적용                               │
│  학습 결과를 다음 작업에 반영                              │
│  - Mode 자동 선택                                         │
│  - Agent/Tier 제안                                        │
│  - Checkpoint 기반 빠른 시작                              │
└──────────────┬───────────────────────────────────────────┘
               │
               └───────────→ (다시 1번으로)
```

**핵심**: 이 루프는 자동으로 돌아가며, 사용자는 명시적으로 "학습하라"고 지시할 필요가 없습니다. 그냥 사용하면, 하네스가 알아서 학습합니다.

## 3가지 아이디어의 시너지

### Session Modes + Meta-Learning

**시너지**:
```
Meta-Learning이 사용자의 Mode 선택 패턴을 학습
→ 자동으로 최적 Mode 제안

예: "금요일 오후엔 항상 Fast Mode 선택"
→ 다음 금요일엔 Fast Mode를 기본값으로 제안
```

### Session Modes + Checkpoint

**시너지**:
```
각 Mode별로 성공 패턴을 별도로 저장
→ Mode에 맞는 Checkpoint Replay

예: "Standard Mode에서 이 타입 작업은 항상 이 순서"
→ Standard Mode 진입 시 해당 패턴 즉시 제안
```

### Meta-Learning + Checkpoint

**시너지**:
```
Meta-Learning이 어떤 Checkpoint를 언제 Replay 할지 결정
→ 상황 인식 재사용

예: "비슷한 작업인데 사용자 스타일이 달라졌네"
→ 과거 Checkpoint를 현재 스타일에 맞게 조정
```

### 3가지 통합

**결과: 성장하는 하네스**

```
처음 (0회 사용)
└─ 모든 것을 물어봄, 표준 설정만 사용

10회 사용 후
└─ 자주 쓰는 패턴 제안, Mode 추천 시작

50회 사용 후
└─ 의도 파악, Checkpoint 기반 빠른 시작

100회 사용 후
└─ 당신만의 맞춤형 하네스, 최소 확인으로 최대 효율
```

## 현재 claude-automate와의 갭

### 현재 제공되는 기능

**Session Context** (`.claude/context/`)
```
- 세션별 컨텍스트 저장
- 날짜별 파일 관리
- 세션 간 연속성 일부 제공

현재 수준: 기본적인 기록
갭: 구조화된 학습 없음
```

**Auto Memory** (`.claude/memory/`)
```
- Claude의 자동 메모리 기능
- 중요 정보 자동 저장
- 장기 기억 일부 가능

현재 수준: 수동적 기억
갭: 능동적 학습 루프 없음
```

### 부족한 부분

**Mode 구분 없음**
```
현재: 모든 작업을 동일하게 처리
필요: Fast/Standard/Deep 구분

갭: 작업 성격에 따른 최적화 불가
```

**체계적 학습 루프 없음**
```
현재: 데이터는 쌓이지만 활용 안 됨
필요: 사용 → 기록 → 학습 → 적용 루프

갭: 반복 작업도 매번 처음처럼 진행
```

**Checkpoint 시스템 없음**
```
현재: 성공 패턴 저장 메커니즘 없음
필요: 구조화된 패턴 저장/재사용

갭: 유사 작업도 처음부터 다시 구성
```

**Meta Profile 없음**
```
현재: 사용자 선호도 추적 안 됨
필요: Tier 선호, 작업 패턴, 승인 스타일 학습

갭: 개인화 불가, 항상 표준 설정
```

## 트레이드오프

### 장점

**점진적 효율 향상**
```
처음엔 느리지만, 쓸수록 빨라짐
100회 사용 후엔 10배 빠른 작업 가능
```

**개인화**
```
당신만의 스타일에 맞는 하네스
다른 사용자와는 다른 최적화
```

**지식 축적**
```
성공 패턴이 자산으로 쌓임
프로젝트 간 재사용 가능
```

**Cold Start 완화**
```
새 프로젝트도 과거 경험 활용
빠른 적응
```

### 위험

**과적합 (Overfitting)**

가장 큰 위험입니다.

```
문제: 항상 같은 방식으로 굳어짐
예시: "항상 Sonnet만 쓰네" → Haiku/Opus 사용 기회 상실

완화 방법:
- Exploration vs Exploitation 균형
- 주기적 랜덤 샘플링 (10% 확률로 새 패턴 시도)
- 사용자 피드백 반영 (수동 Mode 선택 존중)
```

**Cold Start 문제**

초기엔 데이터가 없습니다.

```
문제: 처음 10회는 학습할 게 없음
예시: 모든 것을 물어봐야 함 → 느림

완화 방법:
- 합리적인 기본값 제공
- 유사 프로젝트 Checkpoint 가져오기
- 빠른 학습을 위한 명시적 피드백
```

**노이즈 학습**

잘못된 패턴도 학습할 수 있습니다.

```
문제: 실패한 작업도 기록되면 학습
예시: 우연히 성공한 나쁜 패턴 → 반복 사용

완화 방법:
- 성공률 기반 가중치
- 사용자 명시적 거부 시 강한 페널티
- 주기적 패턴 검증
```

**복잡도 증가**

시스템이 복잡해집니다.

```
문제: 학습 로직, 저장소, 추론 엔진 추가
예시: 단순한 하네스 → 복잡한 학습 시스템

완화 방법:
- 선택적 활성화 (기본값은 꺼둠)
- 명확한 on/off 스위치
- 학습 과정 투명하게 공개
```

**프라이버시 우려**

모든 작업이 기록됩니다.

```
문제: 민감한 정보도 Checkpoint에 저장될 수 있음
예시: API 키, 비밀번호 등

완화 방법:
- 로컬 저장만 사용
- 민감 정보 필터링
- 명시적 동의 필요
```

## 결론

**적응형 하네스**는 단순한 자동화를 넘어, **함께 성장하는 도구**를 만드는 비전입니다.

### 핵심 가치

```
처음엔 표준 도구
쓸수록 맞춤형 도구
결국엔 당신의 분신
```

### 다음 단계

1. **프로토타입**: 가장 단순한 버전부터 시작
   - Session Mode 구분만 먼저 구현
   - 수동 선택, 자동 학습 없이

2. **데이터 수집**: 사용 패턴 기록 시작
   - Checkpoint 포맷 정의
   - 기록만 하고, 활용은 나중에

3. **학습 루프**: 가장 단순한 학습부터
   - Tier 선호도만 학습
   - 빈도 기반 단순 추천

4. **점진적 확장**: 검증된 후 기능 추가
   - Agent 순서 학습
   - Checkpoint Replay
   - Meta Profile 고도화
